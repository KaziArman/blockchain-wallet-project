## Windows Docker Desktop — Critical Networking Fix

On Windows, Docker runs inside a WSL2 Linux VM. `network_mode: "host"` binds to the VM's network, NOT your WiFi interface. This means other devices on your WiFi cannot reach your node.

**Always use explicit port mappings instead:**

```yaml
# WRONG — does not work on Windows Docker Desktop
qbft-launch-bootnode1:
  network_mode: "host"

# CORRECT — works on Windows
qbft-launch-bootnode1:
  ports:
    - "30303:30303/tcp"
    - "30303:30303/udp"
    - "8545:8545"
  command:
    - --rpc-http-host=0.0.0.0    # Must add this
```

> **Note:** On macOS or Linux, the original `network_mode: "host"` works fine. The explicit ports approach works on all platforms.

## IPFS Node Setup

The professor's original image `ipfs/go-ipfs` has been renamed to `ipfs/kubo`. The latest version (0.41.0) has breaking changes for private networks (AutoConf/AutoTLS conflicts with swarm keys). Use v0.28.0:

```yaml
ipfs-node1:
  image: "ipfs/kubo:v0.28.0"
  environment:
    LIBP2P_FORCE_PNET: "1"
    IPFS_SWARM_KEY: |
      /key/swarm/psk/1.0.0/
      /base16/
      76acbaacdcc35520c4b9fe8e87e32f45f3405d4208c8b58bd29a55fadee5e922
  ports:
    - "4001:4001"
    - "5001:5001"
    - "8080:8080"
```

### IPFS Access from Inside Containers

Since `test-smartcontracts` uses `network_mode: "host"`, it cannot resolve Docker service names like `ipfs-node1`. Use `host.docker.internal` instead:

```python
IPFS_API = "http://host.docker.internal:5001/api/v0"
```

Both `host.docker.internal:5001` and `127.0.0.1:5001` work from inside the test container on Windows.

## PHASE 1 — Device 1 Setup (Bootnode1 + IPFS + GridFlex)

### Step 1.1 — Find Your WiFi IP

```powershell
ipconfig
```

Look under **Wireless LAN adapter Wi-Fi** for:
```
IPv4 Address. . . . . . . . . . . : 192.168.1.239
```
This is your `DEVICE1_IP`. Write it down.

### Step 1.2 — Update docker-compose.yml

In `qbft-launch-bootnode1` service:
- Replace `network_mode: "host"` with explicit ports (see fix above)
- Set `--p2p-host=YOUR_DEVICE1_IP`
- Add `--rpc-http-host=0.0.0.0`

### Step 1.3 — Clean Previous Data

Open **Git Bash** from the QBFT-Network directory:
```bash
bash clean.sh
```

This removes `networkFiles/`, `Node1/data/`, `Node2/data/`, and any generated files. Make sure these folders are empty before proceeding.

### Step 1.4 — Generate Genesis Block

```powershell
docker compose up qbft-configure-genesis
```

After running, you should see:
```
QBFT-Network/
├── networkFiles/
│   ├── genesis.json
│   └── keys/
│       └── <public-key-folder>/
```

### Step 1.5 — Move Validator Keys to Node1

```powershell
docker compose up move-keys
```

After running:
```
QBFT-Network/
├── Node1/
│   └── data/
│       ├── key
│       └── key.pub
```

### Step 1.6 — Launch Bootnode1

```powershell
docker compose up qbft-launch-bootnode1
```

**Keep this terminal open.** You should see blocks being produced every 2 seconds:
```

Produced empty block #2 / 0 tx / 0 pending
```

The enode URL will appear in the output. **Copy and save it** — you need it for Device 2:

In a **new terminal**:


Both must show `TcpTestSucceeded : True`.

### Step 1.8 — Launch IPFS Node

```powershell

```

Wait 5 seconds, then verify:

You should see `Daemon is ready` in the output.


```yaml

  - "30303:30303/tcp"
```

Same ports as Device 1 — no conflict because they're on different machines.

### Step 2.3 — Verify Connectivity

## Running Node2 on the Same Machine as Bootnode1

If you don't have a second physical device, you can run Node2 on the same machine. The key difference is port numbers must not conflict:

| Setting | Bootnode1 | Node2 (same machine) |
|---------|-----------|----------------------|
| `p2p-host` | `192.168.1.239` | `192.168.1.239` (same) |
| `p2p-port` | `30303` | `30304` (different) |
| `rpc-http-port` | `8545` | `8546` (different) |
| Docker ports | `30303:30303`, `8545:8545` | `30304:30304`, `8546:8546` |
| Data path | `Node1/data/` | `Node2/data/` (different) |

```powershell
mkdir Node2\data
docker compose up qbft-launch-node2
```

For the dashboard on the same machine, use a different Streamlit port:
```powershell
streamlit run app.py --server.port 8502 -- --port 8546
```

```powershell
docker compose up app-ui --remove-orphans

# Check bid secrets (replace N with round number)
docker exec -it qbft-network-test-smartcontracts-1 python3 -c "
import json, os

round_num = '1'  # <--- Change this to your current round number
file_path = f'/home/test_smartcontracts/gridflex/round_{round_num}_bids.json'

if not os.path.exists(file_path):
    print(f'Error: File {file_path} not found.')
else:
    with open(file_path) as f:
        bids = json.load(f)
    
    print(f'--- Bids for Round {round_num} ---')
    for node_name, data in bids.items():
        # Using .get() to prevent crashes if a node hasn't bid yet
        ask = data.get('ask_price', 'N/A')
        secret = data.get('bid_secret', 'None')
        
        if secret != 'None':
            print(f'{node_name: <20} | Ask: {ask}c | Secret: {secret}')
"
```
