## 1. Project Overview

This project deploys a BasicWallet smart contract on a private Hyperledger Besu QBFT blockchain. The wallet allows users to deposit ETH, the contract owner (Jay) to withdraw a percentage from depositors, and anyone to check balances. The system runs across two physical devices on the same WiFi network, demonstrating a decentralized blockchain network.

### What each component does

- **Bootnode1 (Device 1):** The validator node that produces new blocks every 2 seconds
- **Node2 (Device 2):** A syncing node that downloads all blocks from bootnode1 and maintains its own copy
- **Smart Contract (wallet.sol):** The wallet rules written in Solidity, deployed once on bootnode1, accessible from all nodes
- **Streamlit App (app.py):** A web dashboard where users log in and interact with the wallet
- **CLI Tool (wallet_cli.py):** Terminal commands for debugging individual operations

## 3. Prerequisites

### Both devices need:

- Windows 10/11 with Docker Desktop installed and running
- Both devices on the **same WiFi network**
- Docker images pulled:

```powershell
docker pull hyperledger/besu:latest
docker pull pramanan3/smartcontract_test:latest
docker pull alpine:3.19.0
```

### For Streamlit (both devices):

```powershell
pip install streamlit web3 py-solc-x
```

### Windows Docker Desktop critical rule:

**Never use `network_mode: "host"` for Besu nodes.** Docker Desktop runs inside a WSL2 VM, so "host" mode doesn't bind to your WiFi interface. Other devices on WiFi cannot reach it. Always use explicit `ports` mappings instead.

## 4. Device 1 Setup

### Step 4.1 — Find Device 1's IP

```powershell
ipconfig
```

Look under **Wireless LAN adapter Wi-Fi** for IPv4 Address (e.g., `192.168.1.239`).

### Step 4.2 — Clean previous state (first time only)

Open **Git Bash** terminal:

```bash
cd /c/blockchain_tutorial/qbft/QBFT-Network/
bash clean.sh
```

**WARNING:** `clean.sh` deletes ALL blockchain data. Only run this for a completely fresh start.

### Step 4.3 — docker-compose.yml for Device 1

Your `docker-compose.yml` should contain these services. Replace `<DEVICE1_IP>` with your actual WiFi IP:

```yaml
services:
  qbft-configure-genesis:
    image: hyperledger/besu:latest
    volumes:
      - .:/var/tmp/QBFT-Network
    working_dir: /var/tmp/QBFT-Network
    entrypoint: ["besu"]
    command:
      - operator
      - generate-blockchain-config
      - --config-file=/var/tmp/QBFT-Network/qbftConfigFile.json
      - --to=/var/tmp/QBFT-Network/networkFiles/
      - --private-key-file-name=key

  move-keys:
    image: alpine:3.19.0
    volumes:
      - .:/var/tmp/QBFT-Network/
    working_dir: /var/tmp/QBFT-Network/
    command:
      - sh
      - -c
      - |
        mkdir -p ./Node1/data/
        find ./networkFiles/keys/* -type f -exec cp {} ./Node1/data/ \;
        echo "Keys moved to Node1/data/"
        ls -la ./Node1/data/

  qbft-launch-bootnode1:
    image: hyperledger/besu:latest
    ports:
      - "30303:30303/tcp"
      - "30303:30303/udp"
      - "8545:8545"
    volumes:
      - .:/var/tmp/QBFT-Network
    working_dir: /var/tmp/QBFT-Network/Node1/
    command:
      - --data-path=/var/tmp/QBFT-Network/Node1/data/
      - --genesis-file=../networkFiles/genesis.json
      - --rpc-http-enabled
      - --rpc-http-host=0.0.0.0
      - --p2p-host=<DEVICE1_IP>
      - --rpc-http-api=ETH,NET,QBFT,WEB3,ADMIN
      - --host-allowlist="*"
      - --rpc-http-cors-origins="all"
      - --profile=ENTERPRISE

  test-smartcontracts:
    image: pramanan3/smartcontract_test:latest
    network_mode: "host"
    working_dir: /home/test_smartcontracts/
    volumes:
      - ../../test_smartcontracts:/home/test_smartcontracts
```

### Step 4.4 — Generate genesis block

```powershell
docker compose up qbft-configure-genesis
```

Expected output:
```
qbft-configure-genesis-1  | ... Generating 1 nodes keys.
qbft-configure-genesis-1  | ... Writing genesis file.
qbft-configure-genesis-1 exited with code 0
```

### Step 4.5 — Move keys to Node1

```powershell
docker compose up move-keys
```

Verify: `Node1/data/` now contains `key` and `key.pub`.

### Step 4.6 — Launch Bootnode1

```powershell
docker compose up qbft-launch-bootnode1
```

Expected: blocks minting every 2 seconds:
```
qbft-launch-bootnode1-1  | ... Produced empty block #1 / 0 tx ...
qbft-launch-bootnode1-1  | ... Produced empty block #2 / 0 tx ...
```

**Keep this terminal open.** All following steps use new terminals.

### Step 4.7 — Get the enode address

Open a **new terminal**:

```powershell
cd C:\blockchain_tutorial\qbft\QBFT-Network
docker compose up test-smartcontracts -d

docker exec -it qbft-network-test-smartcontracts-1 bash -c "python find_enode_address.py localhost 8545"
```

Output:
```
enode://c0c0e730f0c72c3199e164aa476ad90e4ecb958889c1000241febbb8a2f878169ba25b393870667bb42f177cdf90664b94beec07e5b0ab1a23aadfa95f49cb70@192.168.1.239:30303
```

**Save this entire string.** You need it for Device 2.

### Step 4.8 — Verify ports are accessible

```powershell
Test-NetConnection <DEVICE1_IP> -Port 30303
Test-NetConnection <DEVICE1_IP> -Port 8545
```

Both must show `TcpTestSucceeded : True`. If not, add firewall rules:

```powershell
# Run as Administrator
netsh advfirewall firewall add rule name="Besu P2P TCP" dir=in action=allow protocol=TCP localport=30303
netsh advfirewall firewall add rule name="Besu P2P UDP" dir=in action=allow protocol=UDP localport=30303
netsh advfirewall firewall add rule name="Besu RPC" dir=in action=allow protocol=TCP localport=8545
```

## 8. Connecting Node2 to Bootnode1

### The `--bootnodes` flag alone may not be enough

On Windows Docker Desktop, auto-discovery often fails. You may see Node2 running but with `Peers: 0` and no blocks importing. If this happens, you must **manually add the peer** using `add_peer.py`.

### Step 8.1 — Start test container on Device 2

Open a **new terminal** on Device 2:

```powershell
cd C:\blockchain_tutorial\qbft\QBFT-Network
docker compose up test-smartcontracts -d
```

### Step 8.2 — Manually add bootnode1 as a peer

```powershell
docker exec -it qbft-network-test-smartcontracts-1 bash -c "python add_peer.py 8545 enode://c0c0e730f0c72c3199e164aa476ad90e4ecb958889c1000241febbb8a2f878169ba25b393870667bb42f177cdf90664b94beec07e5b0ab1a23aadfa95f49cb70@192.168.1.239:30303"
```

Replace the enode URL with your actual enode from Step 4.7.

Expected output:
```
Peer added: {'jsonrpc': '2.0', 'id': 0, 'result': True}
Current Peers: [...]
```

Go back to the Node2 terminal. You should now see blocks importing:

```
qbft-launch-node2-1  | ... Imported empty block #170 / 0 tx ... Peers: 1
qbft-launch-node2-1  | ... Imported empty block #171 / 0 tx ... Peers: 1
```

`Peers: 1` confirms the connection. Node2 will rapidly download all existing blocks, then follow new ones in real-time.

## 10. Accessing Dashboard Without Running Node2

There are two ways Device 2 can access the wallet:

### Option A — Browser only (NOT decentralized)

Just open Device 1's Streamlit URL from Device 2's browser:

```
http://192.168.1.239:8501
```

This does NOT prove decentralization. Device 2 is just viewing a remote website. All data comes from Device 1. If Device 1 goes down, Device 2 loses everything.

### Option B — Own Node2 + Streamlit (DECENTRALIZED)

This is what Sections 7-9 describe. Device 2 runs its own node, has its own blockchain copy, and runs its own Streamlit instance. If Device 1 goes down, Device 2 still has all the data.

**For the assignment: always use Option B.** Option A defeats the purpose.

### Comparison

| | Option A (browser only) | Option B (own node) |
|---|---|---|
| Setup | Zero — just open a URL | Node2 + Streamlit |
| Has own blockchain copy | No | Yes |
| Device 1 goes down | Everything stops | Reads still work |
| Proves decentralization | No | Yes |
| Use for assignment | No | Yes |

## 11. Demo: Proving Decentralization

This section demonstrates that the blockchain is persistent, decentralized, and requires a validator for new transactions.

### Demo 1: Same data on both devices

```powershell
# Device 1
docker exec -it qbft-network-test-smartcontracts-1 bash -c "cd q1_wallet && python wallet_cli.py balances 8545"

# Device 2
docker exec -it qbft-network-test-smartcontracts-1 bash -c "cd q1_wallet && python wallet_cli.py balances 8545"
```

Both show identical balances. The smart contract state is replicated.

### Demo 2: Deposit on Device 1, see it on Device 2

```powershell
# Device 1 — Phil deposits 10 ETH
docker exec -it qbft-network-test-smartcontracts-1 bash -c "cd q1_wallet && python wallet_cli.py deposit Phil 10 8545"

# Wait 5 seconds for the block to sync

# Device 2 — check Phil's balance
docker exec -it qbft-network-test-smartcontracts-1 bash -c "cd q1_wallet && python wallet_cli.py balance Phil 8545"
# Shows: 10.0000 ETH — the deposit propagated!
```

### Demo 3: Deposit on Device 2, see it on Device 1

```powershell
# Device 2 — Cam deposits 15 ETH
docker exec -it qbft-network-test-smartcontracts-1 bash -c "cd q1_wallet && python wallet_cli.py deposit Cam 15 8545"

# Device 1 — check Cam's balance
docker exec -it qbft-network-test-smartcontracts-1 bash -c "cd q1_wallet && python wallet_cli.py balance Cam 8545"
# Shows: 15.0000 ETH — transaction from Device 2 was mined by bootnode1!
```

### Demo 4: Stop Device 1 — reading still works on Device 2

```powershell
# Device 1 — stop bootnode1
# Press Ctrl+C in the bootnode1 terminal
# OR run:
docker compose stop qbft-launch-bootnode1
```

```powershell
# Device 2 — check balances (STILL WORKS)
docker exec -it qbft-network-test-smartcontracts-1 bash -c "cd q1_wallet && python wallet_cli.py balances 8545"
# All balances still visible — data is stored locally on Node2
```

### Demo 5: Stop Device 1 — writing FAILS on Device 2

```powershell
# Device 2 — try to deposit (FAILS)
docker exec -it qbft-network-test-smartcontracts-1 bash -c "cd q1_wallet && python wallet_cli.py deposit Phil 5 8545"
# Hangs or times out — no validator to produce blocks
# Press Ctrl+C to cancel
```

This proves: Node2 has the data (reads work) but cannot create new transactions (writes fail) because the only validator (bootnode1) is offline.

### Demo 6: Restart Device 1 — everything resumes

```powershell
# Device 1 — restart bootnode1
docker compose up qbft-launch-bootnode1
```

```powershell
# Device 2 — may need to re-add peer
docker exec -it qbft-network-test-smartcontracts-1 bash -c "python add_peer.py 8545 <ENODE_URL>"

# Device 2 — deposit works again
docker exec -it qbft-network-test-smartcontracts-1 bash -c "cd q1_wallet && python wallet_cli.py deposit Phil 5 8545"
# Success! Balance updates.
```

No data was lost. The blockchain resumed from where it left off.

## 12. Streamlit UI Walkthrough

### Login flow

1. Open `http://localhost:8501`
2. In the sidebar, select "Jay (Owner)" from the dropdown
3. Click the **Login** button
4. Session Info shows: logged in as Jay, address, and "You are the CONTRACT OWNER"

### Deposit (any user)

1. Login as Phil
2. Click the **Deposit** tab
3. Enter amount: `10`
4. Click **Deposit**
5. Green success message with transaction hash and block number
6. Balance card updates from `0.0000 ETH` to `10.0000 ETH`

### Deposit again (proving accumulation)

1. Stay logged in as Phil
2. Enter amount: `10` again
3. Click **Deposit**
4. Balance updates from `10.0000 ETH` to `20.0000 ETH`

### Withdraw as owner

1. Logout (click Logout button in sidebar)
2. Login as **Jay (Owner)**
3. Click the **Withdraw** tab
4. Green banner: "You are the owner"
5. Select "Withdraw from ALL depositors"
6. Drag the percentage slider to 20
7. Preview table shows: each depositor's current balance, 20% taken, and remaining
8. Click **Withdraw 20% from all**
9. Success message with transaction hash

### Withdraw attempt as non-owner (proving access control)

1. Login as Phil
2. Click the **Withdraw** tab
3. Yellow warning: "Only the contract owner (Jay) can withdraw"
4. Click **Try to withdraw anyway (will fail)**
5. Red error: "Transaction reverted: Only owner can perform this action"

### View all balances

1. Click the **All balances** tab
2. Table shows every depositor with their name, shortened address, and balance
3. Your own account shows "(you)" tag
4. Contract total displayed at the bottom

### Block explorer

1. Click the **Block explorer** tab
2. Table shows recent blocks: block number, transaction count, gas used, timestamp
3. Blocks with `Transactions: 1` contain deposits or withdrawals
4. Enter a specific block number to inspect its transactions in detail

### Transaction log

1. Click the **Transaction log** tab
2. Shows all YOUR recent transactions (deposits, withdrawals)
3. Each entry: block number, tx hash, destination, value, status (Success/Failed)

### Device 1 down — Streamlit behavior on Device 2

1. Stop bootnode1 on Device 1
2. On Device 2's Streamlit, the dashboard still loads
3. Balance cards still show correct values (reading from Node2's local data)
4. Click Deposit → hangs with spinner, eventually times out
5. Restart bootnode1 → deposit works again after re-adding peer

## 13. CLI Commands Reference

All commands run inside the test-smartcontracts container:

```powershell
docker exec -it qbft-network-test-smartcontracts-1 bash -c "cd q1_wallet && python wallet_cli.py <COMMAND>"
```

| Action | Command |
|---|---|
| Check one person's balance | `wallet_cli.py balance Phil 8545` |
| Check all depositor balances | `wallet_cli.py balances 8545` |
| Phil deposits 10 ETH | `wallet_cli.py deposit Phil 10 8545` |
| Phil deposits 10 MORE ETH | `wallet_cli.py deposit Phil 10 8545` (same command) |
| Jay withdraws 20% from all | `wallet_cli.py withdraw-all Jay 20 8545` |
| Jay withdraws 50% from Phil | `wallet_cli.py withdraw-one Jay Phil 50 8545` |
| Phil tries to withdraw (FAILS) | `wallet_cli.py withdraw-all Phil 10 8545` |
| Show contract info | `wallet_cli.py info 8545` |

The last argument is always the RPC port (`8545`).

## 14. Troubleshooting

### Node2 shows "Peers: 0" and no blocks importing

Auto-discovery failed. Manually add the peer:

```powershell
docker exec -it qbft-network-test-smartcontracts-1 bash -c "python add_peer.py 8545 <ENODE_URL>"
```

### "TcpTestSucceeded: False" on port 30303 or 8545

On Windows Docker Desktop, use `ports` mappings in docker-compose.yml, NOT `network_mode: "host"`. Also check Windows Firewall rules.

### "Port is already allocated" error

Another container is already using that port. Run `docker compose down` first, then start again.

### "genesis block hash mismatch"

Device 2 has different genesis data. Delete `Node2/data/` contents, re-copy `networkFiles/genesis.json` from Device 1, restart Node2.

### Streamlit shows "Cannot connect to blockchain node"

The Besu node is not running. Start Node2 first, then run Streamlit.

### Deposit hangs / times out

No validator is online to produce blocks. Check that bootnode1 on Device 1 is running. Re-add peer after restarting bootnode1.

### "BadFunctionCallOutput" error

Node2 hasn't finished syncing. Wait for blocks to import (watch Node2 terminal for `Imported block` messages), then retry.

## 15. Important Rules

### NEVER do these:

- Never run `clean.sh` unless you want to destroy everything and start over
- Never run `deploy_contract.py` on Device 2 — the contract is already deployed
- Never run `qbft-configure-genesis` or `move-keys` on Device 2
- Never use `network_mode: "host"` for Besu nodes on Windows Docker Desktop

### ALWAYS do these:

- Always use explicit `ports` mappings for Besu nodes
- Always include `--rpc-http-host=0.0.0.0` in Besu commands
- Always run `add_peer.py` after starting Node2 if it doesn't auto-connect
- Always run `add_peer.py` again after restarting bootnode1
- Always stop bootnode1 with `Ctrl+C` or `docker compose stop` (not `clean.sh`)
- Always keep `contract_address.json` and `abi.json` — without them the app can't find the contract

### Restarting without losing data:

```powershell
# Device 1 — restart bootnode1 (data preserved)
docker compose stop qbft-launch-bootnode1
docker compose up qbft-launch-bootnode1

# Device 2 — restart Node2 (data preserved)
docker compose stop qbft-launch-node2
docker compose up qbft-launch-node2
# Then re-add peer:
docker exec -it qbft-network-test-smartcontracts-1 bash -c "python add_peer.py 8545 <ENODE_URL>"
```
